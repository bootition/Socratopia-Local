## 一、范围与方法

### 1.1 版本区间与读法

- 逐条通读 **3.0.0 / 3.0.1 / 3.1.0 / 3.2.0 / 4.0.0 / 4.0.1 / 4.1.0 / 4.2.0 / 4.3.0 / 4.4.0 / 4.5.0 / 4.6.0 / 4.7.0 / 4.8.0 / 4.8.1 / 4.9.0 / 5.0.0 / 5.1.0** 的 Theme / Highlights / 功能明细 / Fixes。
- "版本"一列记录该能力的**最早出现版本**；后续版本对同一能力的强化、修正、边界补充合并进"官方要点"，并在版本列用括号标注。
- 3.0.0–3.2.0 中凡是 2.1.1 已具备的能力不计入"新功能"；这一段只保留新增项，以及那些修复里体现出的**新规则**（引用可信度、闪卡忠于真正教过的内容、隐藏旁白不能误伤例句等）。
- 上游 notes 混杂大量运营与客户端形态内容，本审查只保留能落到"本地优先 + 单用户 + DeepSeek 自付 + 中文授课"的能力。

### 1.2 排除项

按任务要求排除：云 App / 跨机同步 / 多设备、书城与 Anthology / AI Book Finder / 购书与书币 / 推荐促销、Agora 社区 / 论坛 / 分享（Pass It On）/ 愿望单、账号订阅支付推荐码、移动端（Android/iOS）、语音 TTS / 录音回放 / Voice Pack、萌宠费曼教学、女娲世界构建 AI、Ask Kira 等云端助手。完整一行清单见**第五节**，正文不再展开。

### 1.3 项目现状对照（先排除"已实现"，避免重复建议）

**已实现，不再建议**：

- 主进程：Electron 安全壳（`contextIsolation` / `sandbox` / 无 `nodeIntegration`）、`safeStorage` 加密 Key、DeepSeek 客户端（`deepseek-v4-pro` / `deepseek-v4-flash`）、流式 chat IPC（token / error / end / usage / cancel）、Prompt 组装器（苏格拉底规则、旁白规则、下课铁律、页面导航规则、授课语言规则、学习者信息、教材片段 + token 预算 + 历史窗口化）、9 个角色索引与读取、教材 `createFromText`（Markdown / text）、conversation 元数据与 message JSONL 持久化。
- 渲染层：安全 Markdown 渲染（streamdown + KaTeX + 代码高亮 + `rehype-harden`，禁 raw HTML）、AppShell / Sidebar、ClassroomContext、`useChatStream`。
- 契约层：Profile / World / Companion / Textbook / Conversation / Message / **Artifact** 的 Zod schema 与 IPC schema（已含 `IpcEndClassInputSchema`、`IpcGetArtifactInputSchema`、`IpcSearchMessagesInputSchema` 等**有契约、无实现**的占位）。

**未实现（本文建议的落点）**：

- Milestone 3 剩余 6 项：设置门、角色选择 UI、教材导入 UI、消息/输入组件、ChatPanel / useConversation、完整闭环接线。
- Milestone 4 全部：课后产物生成与落盘、历史与搜索、进度回写。
- 全库 grep 确认：代码中**没有** pace（节奏）、旁白开关、高亮、笔记、检索、导出、用量统计的任何实现痕迹。

### 1.4 判定口径

- **价值**：只看"本地优先 + 单用户 + 自付 token + 中文授课"这一场景，不评估公开产品的运营价值（拉新、留存、变现一律不计）。
- **可行性**：低 = 需要新格式解析 / 多模态 / 大规模重构；中 = 需要新的本地索引或中等 UI 工作量；高 = prompt / UI / 本地读写即可完成。
- **结论**：建议加入 / 暂缓 / 不做。
- **优先级**：P0 = 课堂闭环必需；P1 = 高价值；P2 = 锦上添花。

## 三、功能详述

### 3.1 P0：课堂闭环必需

**F01 教学节奏与覆盖度控制（Teaching Pace）**
- 版本：3.0.0 引入三档节奏（慢 / 正常 / 快）；4.1.0 让正常与"慢慢来"覆盖更完整；4.3.0 变得更稳、少跳步少重复；4.6.0 把深度收敛成 Auto；4.9.0 让"细致"档不提前跳过教材内容。
- 官方要点：节奏由学习者决定，角色跟随；「掌握一点就跳过相邻的独立知识点」被明确视为缺陷并修掉；遇到真正重复才允许掠过。
- 本地价值：这是苏格拉底课堂最基础的"控制权"旋钮，直接决定一节课的推进速度和 token 消耗，也会影响教材窗口何时前移。
- 可行性：高。conversation 增加 `pace` 字段，prompt 追加节奏规则，UI 放一个三档选择。
- 依赖/风险：与 token 预算、阅读窗口推进逻辑耦合；规则必须写清"何时可以前移"，否则模型会自行脑补。
- 结论：建议加入 · **P0**。

**F02 课堂内教材出处引用（In-class Textbook Citation）**
- 版本：3.0.0 引入聊天气泡内的教材引用按钮（对 Markdown 教材生效）；3.2.0 / 4.1.0 加强可信度（只有能对到确切原文才显示）；4.7.0 要求"你让我查书我就真的读原文，读不到就说读不到"；5.0.0 统一成 "Page N" 口径。
- 官方要点：引用是**可核对**的：没有确切匹配就不显示按钮、不拿别的页顶替；同时教材原文与角色自己的转述必须区分，不能让角色把自己的说法当成教材立场。
- 本地价值：苏格拉底式教学最怕"编教材"。本地导入的是用户自己的材料，引用可核对是信任前提，也是"以教材为中心"教学的基础。
- 可行性：中高。教材按段落切分 + 关键词检索，把命中段落连同 `page`/`section` 一起存到 message 上，右侧/弹层展示原文。
- 依赖/风险：MD 教材需要行号或段落锚点；PDF 需要页码映射；无匹配时的降级话术必须写进 prompt。**这是防幻觉红线，不能省。**
- 结论：建议加入 · **P0**。

**F03 阅读窗口、目录定位与进度提交（Reading Window, TOC & Progress Commit）**
- 版本：3.0.0 引入"当前教材段"概念；4.1.0 让页码/跳页/目录更干净，并可从课堂自身的阅读记录重建上下文；4.4.0 明确"上课时随便翻页只影响当前课堂，只有走完下课流程才成为下节课的起点"；5.0.0 让目录能定位当前窗口、跨节时连续高亮而不是硬指一节。
- 官方要点：进度是"承诺"而不是"随手翻到哪"，翻页与提交分离；旧课堂临时上下文丢失时要尝试自愈，真的确认不了就明说。
- 本地价值：`progress.md` 与 `textbooks/{id}/progress` 已在产品规格里，本项补上"进度语义"和"目录定位"，让下次上课接得上。
- 可行性：高。textbook metadata 已有 `progress { currentPage, totalPages }`；补 `readingWindow`、TOC 解析（MD 标题即目录）与结束时的提交动作。
- 依赖/风险：MD 教材的"页"概念需要定义（建议按章节/段落块，而不是硬造页码）；提交时机必须绑定下课后流程，不能随翻页写盘。
- 结论：建议加入 · **P0**。

**F04 下课二次确认与课后产物重跑（End-Class Confirm & Post-class Redo）**
- 版本：4.0.0 允许只重跑缺失的课后内容；4.6.0 下课加确认框，并说明"重试是否安全"；4.7.0 确认框改成正向说明收益，取消时输入框草稿原样保留；4.9.0 "继续学习"不再依赖角色寄语。
- 官方要点：误点不下课；产物断线/生成失败可只补缺的那部分，不必重上一节课；失败时明确告知能否重试。
- 本地价值：与 Milestone 4 的产物生成直接相关，是实现成本极低但收益明确的一道保险（产物生成要花 token，重跑一次就是真金白银）。
- 可行性：高。Artifact schema 与落盘路径已定，加分步状态 + 幂等重跑即可。
- 依赖/风险：需定义产物的"完成度"判定（5 类产物各自成功/失败/部分成功），否则"只补缺失"无从判断。
- 结论：建议加入 · **P0**。

### 3.2 P1：高价值

**F05 课堂笔记与多色高亮（Classroom Notes & Highlights）**
- 版本：4.6.0 桌面端文本高亮 + 导出 PDF 时可选保留标记；4.7.0 四色高亮、可点开旧高亮改色/删除、导出可保留或出干净版；5.0.0 笔记可锚定到句子/引用/公式，也可写"无锚点"的随想，汇总进课堂笔记本，并可回跳原文；5.1.0 笔记与高亮合并视图、课后仍可编辑、导出时带圈号标注来源。
- 官方要点：笔记与高亮都是**锚定在学习材料上的对象**，不是散的富文本；自己的笔记与课文原文要分开渲染；同一处修改冲突时取"较新的有效状态"。
- 本地价值：本地优先工具的真正差异化——课堂记录能变成自己的学习资料；上游 5.0.0 还要求"笔记参与摘要生成，但保持个人措辞与课堂复述的区分"。
- 可行性：中高。message 级 + 字符区间锚点（`messageId + start/end + quote`），落 `notes/` 与 `highlights/` JSON，渲染层加 mark。
- 依赖/风险：区间锚点在流式消息重渲染后容易错位，必须存 quote 以便自愈比对；公式内的选区要退化为"整式锚点"。
- 结论：建议加入 · P1。

**F06 划词工具条：解释 / 翻译 / 追问 / 标记闪卡（Text-selection Toolbar）**
- 版本：4.7.0 完整成型（高亮、解释、译成中文/英文、把选中段落作为引用放进输入框、标记为闪卡重点）；5.0.0 重排分组并让"解释"更像给初学者的迷你讲解（含常见误解）；4.9.0 要求解释/翻译里公式要正常排版、工具条不跟着跑到别的页面。
- 官方要点：选中文本只是起点，动作要落在"看懂这句话"上；"追问"只把引用放进输入框，**选中本身绝不直接发送**；翻译要考虑整条消息的上下文，不看孤立词。
- 本地价值：对中文用户读英文教材价值最大；对理科公式的解释也需要额外一次小调用，成本可控。
- 可行性：中。需要选区管理、浮动工具条、把引用注入 composer，以及两个短 prompt（解释 / 翻译）；结果可缓存复用，避免重复花钱。
- 依赖/风险：额外 DeepSeek 调用属于"用户没点发送也会花钱"，建议在设置里可关、并显示这是付费动作；公式选区需整式复制（上游 4.9.0 明确单个字形也要复制整条公式）。

**F07 全教材检索式引用与查证（Whole-book Retrieval）**

- 官方要点：检索是**服务于当前讨论的证据补充**，不是每轮例行搜索；教材原文位置、角色自己的延伸、仍不确定的部分三者要分开陈述，反例有效就改，无效就不改。
- 本地价值：本地教材全文索引完全自持，不依赖任何云服务；这是把"课堂"从"聊天"变成"教这门课"的关键。
- 可行性：中。title + 段落切分建本地倒排/轻量向量索引（可先用关键词 + 中文分词），按需检索注入 prompt。
- 依赖/风险：检索结果质量决定体验，需加"最多一次/轮"的预算约束与去重；中文分词和公式片段是明显的坑点。

**F08 课堂偏好设置（Classroom Preferences）**
- 版本：4.8.0 新增。

- 本地价值：几乎零成本换来的个性化——不用再在课上反复提醒；对单用户来说等于"我的教法说明书"，且完全离线保存。
- 可行性：高。profile 级 `classroom_preferences.md` + prompt 注入 + 设置弹层。
- 依赖/风险：自由文本偏好可能与"下课铁律/旁白规则"等硬规则冲突，需要在 prompt 里明确硬规则优先级更高；偏好文本也属于用户内容，注入时要加分隔标记。

**F09 推理深度档位与模型切换（Reasoning Depth）**

- 本地价值：**直接映射到 cost**——Auto/快 = `deepseek-v4-flash`，深 = `deepseek-v4-pro`（项目 client 已支持双模型），在自付场景下是很实在的省钱旋钮。
- 可行性：高。conversation/textbook 级 `reasoningDepth` + 模型选择 + UI 三档。
- 依赖/风险：需要为 Auto 定义可解释的启发式（教材长度/学科/是否含公式），别让 Auto 变成随机；切换模型会造成口吻差异，建议只切模型档位、不改角色 prompt。

**F10 教学法规则升级（Pedagogy Rule Upgrade）**
- 版本：3.1.0 概念型学科提问从学习者经验出发；3.2.0 要求真正讲一章而不是背大纲、闪卡考真正教过的内容；4.3.0 更稳的节奏、减少跳步与过低难度提问；4.4.0 先交代事实/定义/情境再提问、"章节结束"是深入的理由而不是提前下课的理由；4.5.0 不得假设学习者读过教材、一条消息只问一个真问题、不制造假二选一；4.6.0 只读者才知道的术语要先自然给出、每轮推进一个真问题、不得把自身框架说成教材原意；4.7.0 逻辑理解优先于记住名字、反例要真被考虑、课后记忆只记关系与思维方式的真实变化；4.9.0 掌握后转向应用/下一个想法/自然收尾；5.0.0 陌生表达先讲具体对象与关系再推理、问候与闲聊不要当成"缺少审校材料"。
- 官方要点（合并）：先立情境 → 再提问 → 一轮一问 → 术语在解释后给出 → 教材立场与角色推断分离 → 会了就往前走、别机械重复。
- 本地价值：这是"体验好不好"的头号变量，且**不需要任何新架构**，全部落在 `src/main/prompt/rules.ts` 与快照测试上。
- 可行性：高。逐条写成规则段落 + snapshot 测试即可。
- 依赖/风险：**与现状冲突**——现有 `getNarrationRules()` 硬性要求"每条消息必须含旁白、必须以提问结尾、正文 ≤120 字"，而"先给必要事实"必然超字数、"该收尾时收尾"必然不提问。建议把这三条改成分档/可配置（如 `strictSocratic` vs `balanced`），并保留 F18 的旁白开关。
- 结论：建议加入 · P1（与 F01/F11 同一批做）。

**F11 开场、暂停与下课的角色内语义（In-character Opening & Pause）**
- 版本：4.2.0 首课不再空对话开场、角色自然开场、刷新或连点不会重复开场；4.7.0 想暂停时角色保持在设定内、轻声提醒"下课"而不是讲界面按钮；4.8.0 暂停时角色内自然收尾；4.9.0 明确说"先到这儿"时角色在情境中收尾；5.1.0 连接失败可在同一课堂重试而不必重建课堂。
- 官方要点：界面操作不该出现在角色台词里；开场白应带出角色语气与本节话题；开场动作必须幂等。
- 本地价值：直接决定第一次使用的观感；也让"今天就到这儿"这种自然表达不会被角色当成界面指令。
- 可行性：高。开场白由一次调用生成并落盘（带 `openedAt` 幂等保护），配合 prompt 规则。
- 依赖/风险：与现有 `getEndClassRule()`（"绝不要暗示、提议或主动结束课堂"）**需要放宽**：建议改为"不得主动推进下课流程，但学习者表达结束时可以在角色内收尾，并轻声提示保存课堂"。这条改动要同步更新 snapshot 测试。

**F12 闪卡质量规则与完全可编辑（Flashcard Quality & Editability）**

- 依赖/风险：需要为 LLM 输出定义严格的 flashcards schema（现有 Artifact 只存 `content: string`，建议改成结构化 JSON + 原始文本兜底）。

### 3.4 暂缓与不做

**F38 学习档案口令锁（Profile Password Lock）— 不做。** 3.0.0 引入为学习档案设置密码。本机单用户场景下收益极低：数据文件、教材、对话都是明文落在磁盘上，给应用层加一把锁只会制造"已加密"的错觉；真要保护应该用系统级磁盘加密（BitLocker / FileVault）或私密目录。结论：**不做**。

**F39 AI 代写学习者回复（AI Reply）— 暂缓。** 4.6.0 引入、4.8.0 强化（产出可直接发送的第一人称发言，无旁白、无引号、代词正确）。技术上很便宜（一次小 prompt），但与本项目"学习者自己表达"的教学初衷存在张力，用时容易变成"让 AI 替自己学"；且它与 F08 课堂偏好、F10 规则升级共用同一注入通道，晚做不影响架构。结论：**暂缓**，等自用一段时间后再决定是否作为可选开关。

**F40 多伙伴课堂（Multi-companion Group Chat）— 暂缓。** 该能力早于 3.0.0（2.x 已有，故不计入本次"新功能"），本次区间内只有相关修复（3.1.0 卡片对齐、3.2.0 长消息、4.1.0 输入框、4.9.0 排队消息）。本地数据模型已预留 `npc_a/b/c` 槽位，先把单角色课堂做稳，再评估是否同时出场 2–3 个角色。

## 四、建议的落地批次

### Batch 1：课堂闭环收尾（对应 Milestone 3 剩余 6 项）
Milestone 3 剩余（设置门 / 角色选择 / 教材导入 / 消息组件 / ChatPanel / 闭环接线）+ **F01 节奏** + **F02 教材引用（当前窗口最小可用）** + **F18 旁白开关** + **F04 下课确认** + **F16 的重试不丢消息**。
**一句话验收标准**：从"设置 Key → 选角色 → 导入教材 → 角色开场 → 流式对话（可查当前段落原文、可切节奏）→ 下课确认"全流程可用，重启后课堂与消息完整恢复，API Key 不出现在 renderer。

### Batch 2：课后闭环与数据安全（对应 Milestone 4）

## 七、红队对抗审查结论（2026-09-14）

对三块新扩展（多格式导入、进度可视化、自定义角色）与既有课堂/产物链路做了两路对抗审查（主进程/导入与渲染器/集成），共确认 20+ 项问题并全部修复：

**高危（数据完整性/一致性）**
- 切换同伴/教材有 4 个入口不清空 conversationId → 会话记录与实际对话错配；已收敛为 `selectCompanion/selectTextbook`（同值不重置），4 个入口统一调用
- 下课部分失败后「只重试未完成项」因 conversationId 被清空而失效，且历史页无重试入口 → 结束态快照 conversationId + 历史页接通 `onRedo`
- 编辑角色 A 时点 B 的「编辑」会用 A 的数据覆写 B → 表单按 id 重新挂载（key）
- `index.json` 裸写覆盖 + 自定义角色只存索引 → 改为临时文件 + rename 原子写；索引丢失/损坏时从 `comp_custom_*.md` 自动重建（并修复了「其他」性别无法解析导致恢复失败的问题）
- 没有单实例锁，两个实例会互覆盖 → `requestSingleInstanceLock` + 二次实例聚焦已有窗口

**中危（资源/竞态/降级）**
- 流式中发送消息被静默丢弃且清空输入框 → 流式期间禁止发送并保留草稿 + 提示
- 流式中离开课堂不取消 → useChatStream 卸载时 cancel
- 「停止」会把截断回复持久化 → `SendResult.cancelled`，取消的草稿不落盘
- `messages:update` 全量重写与 append 竞态丢回复 → 按会话串行化；流式期间隐藏编辑入口
- EPUB 累计解压无上限（zip bomb）→ 章节循环内累计上限 + container/OPF/单条大小检查
- EPUB href 裸 `%` 触发 URIError（回归）→ 安全解码回退；fragment 正确剥离；被跳过章节现在会统计并提示
- 删除教材/角色后旧课硬报错 → 教材缺失降级为无教材、同伴缺失改为只读回看（发送禁用）
- 进度页码可能超过总页数 → 写入时夹紧 + 展示/ARIA 夹紧
- 偏好设置并发读改写丢字段 → 主进程串行队列
- 启动时任一无障碍的候选角色文件都会让应用起不来 → 逐文件降级 + 候选目录缺失非致命 + initDataDir/ whenReady 兜底
- 打包把测试残留与渲染端依赖复制进 asar → files 排除 + 渲染端依赖下沉 devDependencies（asar 187MB → 23.8MB）

**低危/体验**
- CSP 与 Markdown 图片协议冲突（`img-src`）；导出 Markdown 转义行首 `<`；粘贴/文件导入补齐 4M 字符与 100MB 上限
- 流式期间 aria-live 逐 token 播报 → 流式时关闭 live region；下课确认框支持 Esc 与初始焦点；划词工具条支持 Esc
- 编辑中切换对象会丢草稿 → 阻止切换；导出进行中重复点击 → 单次导出；重试改用最新持久化文本
- 测试不再污染 `out/` 与硬编码 D: 盘路径

所有修复均带回归测试；期间用例数 759 → 813。
